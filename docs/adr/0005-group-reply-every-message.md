# 群里每句话都回（`groupReply: all`）

机器人被授予「群内全部消息」后，网关会把群里每一条消息都推过来（`GROUP_MESSAGE_CREATE`），@ 的消息也走这个类型，靠 `mentions[].is_you` 区分。默认实现只回应 @，用户明确要求改成**每句都回**。

## 决定

- 配置项 `groupReply`：`'mention'`（默认）| `'all'`。本机配置为 `all`。
- `all` 下每条人类消息都起一轮 agent 并回复。
- **`author.bot === true` 一律忽略**：群里有别的机器人、或我们自己发出去的消息被推回来时，否则会无限对话。

## Consequences

- **成本随群活跃度线性增长**：群里每说一句就是一次模型调用。一个二十人的群正常聊天，一小时可能上百次。
- **刷屏**：agent 会对每句话都作答，包括「哈哈哈」「收到」这种。这是 `all` 的固有代价，不是 bug。
- **串行队列会积压**：`maxConcurrent` 默认 1，同群消息按序排队。热闹时段回复会明显滞后，且滞后期间群里还在继续产生新消息。
- **注入面变大**：群里任何人都能通过普通消息把指令送进 agent 的上下文，而 agent 有 `workspace-write` 的写权限。这与 ADR-0004 记的读泄露是同一类风险，叠加后更值得警惕。
- 想回退：把 `groupReply` 改回 `mention` 重启即可，不需要改代码。
