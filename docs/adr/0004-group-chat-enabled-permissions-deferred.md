# v1 接入群聊，群侧权限留待后续

`ADR-0003` 把群 @ 挡在门外，理由是沙箱只挡写不挡读——群里任何人 @ 一下，就能让 agent 读整台机器上的文件并念回群里。这条推理成立，但用户决定：**群聊现在就要能用，群侧的权限与隔离最后再解决**。

所以 v1 的行为改成：

- 群 @ 与私聊一样建 Session、跑一轮、回话，会话键 `group:<group_openid>`，群内共享上下文、消息前缀标发言人。
- 群聊与私聊用**同一档权限**：`workspace-write` + `never`。
- `allowedGroups` 与 `allowedUsers` 同形（空数组 = 不限制），先给一个能收口的旋钮，但默认不限制。

## Consequences

- **已知风险，不是已解决的风险**：群成员可以让 agent 读 `~/.ssh`、`.env`、其它仓库，并把内容发回群里。v1 接受这个风险，因为它只在自己建的测试群里跑。
- 真正的收口要么给群聊裁剪工具集（去掉 `read`/`bash` 的读取面），要么引入可信身份边界，那是独立的一次改动；`allowedGroups` 只是白名单，挡不住群内成员。
- 私聊侧的结论（`workspace-write` + `never`、不注册审批应答者、无审批超时）不受影响，继续有效。
- `ADR-0003` 的其余部分仍然成立，只有「群聊不建会话」这一条被本文件取代。
