# 被动回复靠错误码降级，不用本地时钟预判窗口

被动回复有有效期与次数上限（群 5 分钟 / 5 次，私聊 60 分钟 / 4 次），而一轮 dsh 可能跑几分钟，窗口随时可能在我们发出答案之前就死了。直觉做法是本地记下收到消息的时刻、算着快到期就直接改走主动推送；我们没那么做，而是**先发被动、看服务端返回的错误码再降级**——`40034005` / `304103` / `304027` / `40034128` / `40034024` 命中任意一个，就把本轮标记为粘性失效，同一条内容改走主动重发，后续段落不再试被动。

理由有两层。其一，官方文档自己就矛盾：C2C 发送接口页顶部写「被动消息有效时间 60 分钟」，同页 `msg_id` 字段描述却写「5 分钟内有效」，本地预判必须赌一个数字，赌保守会白丢本来能用的被动额度，赌宽松会静默超时。其二，被动回复是**唯一必然送达**的路径，主动推送可能被用户关掉（`40054013`）、可能没权限（`40034105`）、还占独立配额，所以任何「提前放弃被动」的判断都在拿确定性换一个猜测。代价是慢轮次会多一次失败请求，以及必须把错误码分支表写全——这个代价是可接受且可测的。

## Consequences

- 错误码表就是降级逻辑本身，改发送层之前先看这张表；新增错误码要同步加分支，否则会被当成「其他 4xx，不重试」吞掉。
- 主动推送失败（`40034100` / `40034105` / `40054013`）意味着这一轮彻底发不出去，日志必须留 `err_code` + `trace_id`，否则线上查不出「为什么没回」。
- 不要「顺手优化」成基于时间的预判。那不是简化，是把文档矛盾重新引进来。
